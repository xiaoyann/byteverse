## 今日概览

目标是把后台系统里剩下的三个表单页（登录、投放配置、账号绑定）从手写 loading 状态迁移到 React 19 的 `useActionState`。

结论先说：**代码量少了约 240 行，交互一致性问题一次性收敛**。但迁移过程里有两个坑值得记下来。

## 改动前后对比

之前每个表单都长这样，三份几乎一模一样的样板：

```tsx
const [loading, setLoading] = useState(false);
const [error, setError] = useState<string | null>(null);
const [data, setData] = useState<Result | null>(null);

const handleSubmit = async (e: React.FormEvent) => {
  e.preventDefault();
  setLoading(true);
  setError(null);
  try {
    const result = await submit(form);
    setData(result);
  } catch (err) {
    setError(err instanceof Error ? err.message : '未知错误');
  } finally {
    setLoading(false);
  }
};
```

现在：

```tsx
async function submitAction(_prev: State, formData: FormData): Promise<State> {
  const result = await submit(Object.fromEntries(formData));
  return result.ok ? { data: result.data } : { error: result.message };
}

function Form() {
  const [state, action, pending] = useActionState(submitAction, initialState);
  return (
    <form action={action}>
      {/* pending 直接给按钮，不用再手动同步 */}
      <button disabled={pending}>{pending ? '提交中…' : '提交'}</button>
    </form>
  );
}
```

关键收益不是少写几行，而是 **pending 状态的生命周期由 React 托管**，不会再出现「请求失败但按钮还是 disabled」这类状态不同步的 bug。

## 两个坑

> **坑 1：`useActionState` 的 action 必须是稳定的引用。**
> 在组件内部用箭头函数定义再传进去，每次渲染都会生成新函数，导致 state 被重置。必须提到组件外，或者用 `useCallback` 包住。

> **坑 2：`<form action>` 里的 `FormData` 不包含未命名的 input。**
> 迁移时有两个受控组件忘了加 `name`，提交后后端直接返回 400。建议写一条 ESLint 规则或者在 `submitAction` 里断言 key 数量。
