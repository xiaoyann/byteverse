## 今日概览

截至今天 08:00（UTC+8），过去 24 小时的主线是「AI 基建开始算账」：微软停租 Oracle 的老 GPU 算力并收缩 neocloud 合同，纳斯达克单日回调把 Anthropic 的 IPO 定价打到 1.1 至 1.3 万亿美元区间。模型侧在另一个方向加速——Thinking Machines 的 Inkling 2 Small 用 594B 总参、17B 激活拿到 Artificial Analysis 智能指数 31，并承诺下周按 Apache 2.0 放权重。工程侧最值得读的是 Firecracker 的 guest 到宿主 root 链路，它说明沙箱边界取决于部署细节，而不是 hypervisor 名字。

## 产品发布与更新

- **[Cursor 让 agent 接电话：语音聊天进 IDE、Web 和 iOS](https://cursor.com/changelog)**（Cursor Changelog，11-06）

  在 agent 空闲、输入框为空时点波形按钮可以发起实时语音通话，边说边让它改代码；agent 干活期间对话不中断，可以问「这个 diff 改了什么」、查询这次调用之前的消息，或者在一个 Project 的多个 worker 之间切换。agent 自己也会用短语音汇报进度，而不是把整段文字念出来。底层是 Grok Voice，音色可换；开启 Privacy Mode 时语音链路零数据保留。iOS 上支持「Hey Siri, call Cursor」以及锁屏 Live Activity 挂断。

- **[Perplexity 把 agent 变成「同事」：Teammates 只对 Max 开放](https://www.theverge.com/ai-artificial-intelligence/1028302/perplexity-teammates-ai-agents-work)**（The Verge，11-05）

  Teammates 是常驻 agent，每个有自己的会话线程、独立桌面与浏览器会话（cookie 分开保存），可以直接继承你已有的 Projects、skills、memory 与权限，也能在 Slack 频道里被派活、在彼此之间交接任务。代价是门槛：需要 200 美元/月的 Max 订阅，首发只有 Web，iOS 随后。真正要留意的是权限继承——省掉了重复配置，但一个配错的权限等于把钥匙交给一个会自己干活的程序；另外持续监控加浏览器会话烧 credits 的速度，官方没有给出可用额度。

- **[devvm：一个项目一台 VM，给 coding agent 准备的沙箱](https://devvm.dev/)**（devvm 官网，11-06）

  `cd` 进任意项目目录跑 `devvm`，它按项目文件推断需要的工具链并建一台 VM，然后把 shell 开在里面，Claude Code、Codex、opencode 都在 VM 内运行，登录凭证留在宿主机（`devvm agent login claude` 处理这一步）。免费开源，默认 Lima 后端，已测 Apple silicon Mac 与 Linux 的 arm64/x86_64，Intel Mac 还不支持；需要 `/dev/kvm`，建议 8 GiB 内存与 4 核。对同时开多个 agent 会话的人来说，这是把「每个 agent 一个干净环境」变成默认动作的低成本办法。

- **[Vercel AI Gateway 内置搜索与抓取，按请求计费](https://vercel.com/changelog/ai-gateway-adds-deepseek-search-and-fetch-tools)**（Vercel Changelog，11-06）

  DeepSeek Search 返回相关页面的标题、URL 与摘要，DeepSeek Fetch 把页面正文取回成 Markdown 给模型读，两个工具可以用同一个 Gateway key 配给任何支持工具调用的模型，不需要单独开 DeepSeek 账号，换模型供应商时工具不用换。价格是每 1000 次计费请求 0.75 美元，失败、超时与空结果不计费，模型 token 另算；要求 AI SDK 6.0.321 或 7.0.160 以上。要注意搜索的 fallback 由模型自己决定，供应商顺序与重试次数只是 best effort。

## AI 技术

- **[Thinking Machines 放出 Inkling 2 Small：594B 总参、17B 激活](https://thinkingmachines.ai/news/inkling-2-small/)**（Thinking Machines，11-06）

  这是个 MoE 模型，支持图像输入和可变推理力度，Artificial Analysis 智能指数拿到 31，官方称在 agentic coding、视觉、知识工作与推理上全面提升。目前先在自家 Tinker 上以闭权重提供，等外部安全测试与红队完成后，计划下周按 Apache 2.0 放出完整权重——这个「先闭后开、附带安全测试」的节奏，正在变成开放权重模型的新惯例。训练侧值得注意的一点是它不再只靠单元测试当奖励，很多任务用 agentic RL grader 评价解题过程，模型也被以 Fledge-Alpha 的代号放到 OpenCode 上真实试跑过。

- **[OpenAI 发布 GPT-6 Cyber：ExploitGym 48.5%，越界率降到万分之一](https://openai.com/index/introducing-gpt-6-cyber/)**（OpenAI，11-05）

  相比 GPT-5.6 Cyber，它在 ExploitGym（能否利用指定漏洞）上从 32.1% 升到 48.5%，相对提升 51%。同样关键的是守界能力的抬升：在单独的对照评估里，不加部署提示词时有 99.93% 的测试避开了攻击范围外的服务，加上提示词后是 100%。实战成果包括 Firefox 里 81 个此前未知的高危漏洞（Mozilla 已按 MFSA 2026-118 发布修复）以及配合完成的 Linux 内核提权利用研究；Cisco、Calif、CodeRabbit 的安全团队在用。能力与守界同时上涨，是这个模型相对上一代最有信息量的地方。

- **[Gemini Omni 1.2 Flash：15 秒原生视频，价格降三成](https://blog.google/innovation-and-ai/technology/developers-tools/introducing-gemini-omni-1-2-flash/)**（Google，11-05）

  视频时长从 1.1 的 10 秒提到原生 15 秒，并且可以按 1 秒步进指定 3 到 15 秒；720p 报价 0.07 美元/秒，比上一代便宜 30%。更实用的是工作流：可以先用 360p 或 720p 快速起草，靠多轮对话改一个细节而不是整条重生成，最后把满意的结果上采样到 1080p 或 4K。参考图遵循能力也加强了。已在 Gemini API 与 Gemini for business 全面可用，不是预览。

- **[小模型当裁判、拿不准再问 Opus：4 倍便宜拿到前沿准确率](https://hightouch.com/blog/llm-judges-identity-resolution)**（Hightouch 工程博客，11-06）

  他们用身份归并（把多条记录映射到同一个人）的评分做测试床，让 Jev、Luna 两个决策模型做 LLM judge。裸跑时两者准确率在 88.8% 到 97.3% 之间，Luna 更强，但在硬样本上差距消失；真正的差异在置信度校准——Jev 的错大多伴随低置信，Luna 的错大多伴随高置信。于是 Jev 加 Opus 的混合方案能在前沿准确率下把成本压到四分之一以下。决策模型本身便宜 90 倍、快 10 倍以上（每千条 0.05 到 0.10 美元、约 0.15 秒），代价是硬样本上落后 Opus 约 6 个百分点。结论来自单一任务与单一供应商数据，别直接外推到所有评测场景。

- **[Claude 自己签发身份断言，Supabase MCP 不用再逐个点同意](https://supabase.com/blog/claude-issued-enterprise-managed-auth-for-mcp)**（Supabase，11-03）

  MCP 的企业托管授权扩展此前只有 Okta 支持，多数 IdP 还没跟上。现在组织 owner 或 admin 批准 Claude 并把它注册为 issuer 之后，每个有对应 Supabase SSO 身份的成员就能用现有角色直接访问，不再需要每人过一次同意页，IdP 侧什么都不用改。机制是 Claude 自己签一份短期 ID-JAG（Identity Assertion JWT Authorization Grant），签发前先校验这个人是不是当前成员、这份断言是不是只对 Supabase 有效。Supabase 侧对配好 SSO 的 Team 与 Enterprise 组织正式可用，Claude 的 auto-connect 仍是面向 Team/Enterprise 的 beta。

## 大前端与后端

- **[Expo 用 Kolibri 换掉 fbjni：C++ 调用快 28 到 51 倍](https://expo.dev/blog/expo-modules-2-0-new-jni-layer)**（Expo 博客，11-06）

  Kolibri 是 Expo Modules 2.0 在 Android 上的 JNI 库，用来替换 fbjni，分三块：一个只依赖 `<jni.h>` 的 C++ 库、一个小 Kotlin runtime、一个在编译期消掉 JNI 样板代码的 Kotlin 编译器插件。优化思路很具体：对不可能抛异常的方法跳过 `ExceptionCheck`，把 `JNIEnv` 当参数传进去而不是每次查，hybrid object 由编译器插件把 C++ 指针直接交到 native 侧，scope 一次性释放挂在某个 JS runtime 上的所有对象。JS 对象不再逐个 JNI 调用拼出来，而是走共享二进制缓冲送进 Kotlin，比逐个建对象快 3 到 5 倍。做原生模块的人值得对着自己的调用链算一遍这笔账。

- **[Chat SDK 的 agent 现在能边写边流出 UI 卡片](https://vercel.com/changelog/json-render-and-chat-sdk-agents)**（Vercel Changelog，11-06）

  做法是给组件目录加上类型，agent 写一份 JSON spec，`json-render` 把它转成 Chat SDK 卡片，再由每个 adapter 翻译成平台原生格式——Slack 出 Block Kit，Teams 出 Adaptive Cards。`streamCard` 在根元素一有内容就先发出去，之后随新元素流式更新，默认最多 500 毫秒改一次。`toCard` 会逐字段对照 schema 校验，非法就抛 `CardSpecError`，并把每个问题整理成可读列表回给模型重写。平台有单条消息容量上限，adapter 默认会降级（Slack 把第二个表格变成代码块），传 `limits` 可以直接拒绝。相比让模型生成 HTML，这条路让输出落在平台自己的结构里，可校验、可降级。

- **[Cloudflare 想把隐私通行证搬到后量子：MOLE 与盲签名](https://blog.cloudflare.com/vole-mole/)**（Cloudflare 博客，11-06）

  Privacy Pass 靠发 token 换访问权，token 与签发对象不可链接，用来在不上验证码、不建账号的前提下做速率限制。问题是它依赖 RSA 与椭圆曲线，量子攻击者可以伪造 token 绕过限速；好在不可链接性是无条件成立的，隐私不会因 Q-day 失效，所以还有腾挪空间。真正的难点是体积：ML-DSA-44 签名 2420 字节，ECDSA-P256 只有 64 字节，没有可直接替换的方案。文章梳理了盲签名设计的新进展，一个候选是 MOLE（Moderation Of unLinkable Endorsements），明确目标之一就是管理 agent 流量——这块会和后面的 Firecracker 条目一起，构成「怎么对待非人类访客」的两种思路。

- **[从 guest 到宿主 root：把 Firecracker 的 vCPU 线程改写掉](https://pwn.ai/blog/firecracker-escape)**（pwn.ai，11-06）

  这是 PwnEscape 系列第二篇。基础漏洞 CVE-2026-99999 在 Linux 的网络栈：校验和卸载让 guest 可控的元数据在 IPv4 头通过校验后被改写，实测能把头长度从 20 字节改成 60 字节，每次触发泄露 32 字节宿主内存，CVSS 9.3，8 月在 Vercel 的百万美元沙箱挑战中被发现。本篇做的是后续跳板：用第一部分的宿主内存读写原语定位 guest 页在宿主的位置、走 EPT 找到 Firecracker 进程的页表、在 ASLR 下定位二进制，再找到停在 `KVM_RUN` 里的 vCPU 线程的 `pt_regs`，改掉返回路径，让 VMM 以 root 执行一条 `write(2)`，而 VM 全程在线。

  限制必须说清楚：目标环境是 Firecracker v1.16.1 未启用 jailer、以 root 直接启动，作者明确不声称任何厂商生产环境可拿到 root；漏洞在宿主内核而不是 Firecracker 本身。修复提交是 `6785011f8b16`，对应各稳定分支 5.10.272、5.15.223、6.1.190、6.6.159、6.12.113、6.18.57、7.2.11，且必须升宿主内核，只升 guest 没用。自建 sandbox 的人可以顺手查两件事：jailer 有没有开，宿主内核在不在修复版本之上。

- **[把 Blender 的 GUI 拆出来当库用，支持 React 与 Rust](https://github.com/ppmpreetham/BUI)**（GitHub，HN 热帖 11-06）

  BUI 把 Blender 的界面代码从主仓库解耦成独立库，提供 Python、Rust、JavaScript（React、Svelte）、C、C++ 与 Dear ImGui 的绑定，已发布到 PyPI、crates.io 与 npm（`@blender-ui/react`）。作者的说法是 Blender 的 GUI 经过几十年优化，比 GPUI 快一倍——这是自述，没看到第三方复现，先当参考。许可证是 GPL-3.0-or-later，商用产品集成前要先把这一条看清楚。
