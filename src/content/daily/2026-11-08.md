## 今日概览

截至今天 08:00（UTC+8），过去 48 小时最值得读的一条不是模型发布，而是一位研究者对组织路线的公开复盘：微软研究院的 AI Frontiers 被并入 Microsoft AI 两个月后实际解散，负责人 John Langford 写清了「只做 scaling、不做研究」的分歧在哪。同一天 Anthropic 把智能体记忆拆成可实现的四层结构，用 CL-Bench 和《宝可梦红》给出「少而精的记忆比多而杂更好」的实测。工程侧最该动手的是 Apiiro 的扫描结果：Claude Code 的「是，别再问了」会把带密码的完整命令写进项目文件，GitHub 上有 1,122 份这样的公开文件。

## 行业动态

- **[微软研究院 AI Frontiers 团队解散，负责人公开路线分歧](https://hunch.net/?p=13764006)**（John Langford 个人博客，11-06）

  AI Frontiers 是 2023 年 ChatGPT 发布后在微软研究院内部组建的子组织，约 50 人，产出过 AutoGen 编排框架和 Fara 电脑操作 agent，纽约部分则做更基础的方向——可外推的 Next Latent 目标、改进版 Muon（Dion3）、靠递归提升模型能力的 Full Bandwidth Transformer。今年 9 月初它被重组进 Microsoft AI，作者称来自 ex-Inflection 管理层（即 MAI）的核心哲学是「scaling，并且坚决不做研究」，与团队方向不兼容，而且「有大量证据表明他们并不真的想要我们」。他选择离开，其余创始管理层成员也得出相似结论，明年不会再有该团队的实习名额。

  这篇值得读的原因不是人事，而是它把「研究回报」这笔账摊开了：作者引用字节的实验称，Full Bandwidth Transformer 的一个变体可能等效于两倍参数量的模型——在行业累计投入接近一万亿美元的背景下，训练与推理成本减半值多少钱，是可以算的。他还点名了微软研究院的一层隐忧：把做好工作与好结果之间的默认契约打破了，以后类似的重组还会发生。

## 产品发布与更新

- **[Cursor 让 agent 直接把应用发到线上，附安全门禁](https://cursor.com/changelog/build-live-apps)**（Cursor Changelog，11-05）

  在 Cursor 里起一个 cloud agent 并明确说「要建应用」，它会脚手架出 Web 应用、按需拉起 Postgres、把认证接到 Cursor SSO 后面、配好托管，最后给你一个自选域名的可访问链接。要连内部系统（比如数据仓库）时，agent 会主动向你索要对应的 secret。

  发布前的门禁是重点：Cursor 会跑确定性检查与 agent 式检查，专抓「密钥写进应用文件」「凭证暴露」这类常见错误，任一项不过就不上线，由 agent 告诉你还要修什么；团队管理员能看到全团队的应用与 secret 清单、给安全审查加自定义规则、批准被拦下的发布，或直接下线任何一个应用。已支持 Cursor Origin 与 GitHub 仓库，GitLab 在路上；功能对所有开通 cloud agent 的付费套餐开放，个人套餐还可以公开分享应用。

  它解决的是「内部小工具死在 localhost」这个老问题，代价是把代码、数据库、密钥、托管、访问控制收进同一条 agent 流程——用之前先把「谁能发布、谁能批准被拦的发布、谁能读哪个 secret」这三件事定下来，比试用本身更重要。

- **[Render Sandboxes 公测：给每个 agent 一台 Firecracker 微虚拟机](https://render.com/blog/introducing-render-sandboxes)**（Render 博客，11-04）

  每个 sandbox 是独立的 Linux 环境，通常一秒内可执行第一条命令，可以长期运行（多天的迁移任务不会丢进程和内存），空闲 15 分钟后自动快照并挂起，挂起期间不计 CPU 与内存，只算快照存储。计费按实际使用的 CPU 加分配的内存，等模型或等人不算 CPU 时间。

  两个设计值得借鉴。一是快照分两级：文件系统快照只存文件与装好的工具，运行时快照连内存和运行中的进程一起存，恢复后从中断处继续，官方称启动快 3 到 10 倍。二是出站网络策略可以设为「全部放行 / 仅白名单域名 / 完全禁止」，配合凭证代理（sandbox 内的代码不带凭据发请求，代理在外侧为允许的域名补 key），把提示注入能造成的损失限制在「拿不到密钥」。凭证代理与细粒度 API key 还在早期访问阶段，sandbox 本身已在俄勒冈区域对所有 workspace 套餐开放，TS/Python SDK 与 CLI 都能操作。

- **[LiveReview：按风险打分，自动放行最安全的 30% 到 50% PR](https://github.com/HexmosTech/LiveReview)**（GitHub / Product Hunt，11-07）

  思路借自 Meta 内部的 RADAR：不是给 PR 加更多评论，而是先判断这次改动值不值得人看。每个 PR 拿一个风险分，最低的一档直接自动批准，其余按爆炸半径排序后送给人；粒度细到 diff 里的每个 hunk——三行改共享鉴权可以排在三百行 UI 调整前面。分数由三路信号合成：LLM 读改动在做什么、一个用你自己历史事故与回滚训练的 ML 模型、以及基于调用图的静态分析。

  检查点覆盖 commit、push 前、PR、CI/CD 与定时扫描，可按仓库开关；CI 门禁写成一条 jq 规则，比如「有任何安全类发现就拦」。另有 Cognitive Coverage 给每份 review 生成 60 秒摘要卡片和一份基于 diff 的小测验，用来对付「人批准了自己没读懂的 AI 代码」。项目免费且可自托管，支持 GitHub/GitLab/Bitbucket/Gitea/Azure DevOps，可复用手上已有的 Claude 或 OpenAI key。

  需要打折看的是效果数据：50 倍事故减少、3 倍回滚减少、审查快 35% 都是 Meta 自述的成果，不是这个工具在你仓库上的实测；风险模型要真正好用，得先有自己的事故与 override 数据可学。

## AI 技术

- **[Anthropic 拆解智能体记忆：日志、笔记、知识表征与离线「做梦」](https://www.anthropic.com/research/components-of-agent-memory)**（Anthropic，11-06）

  先把定义收紧：这里的记忆只指跨会话保留、以可读取的上下文形式存下来的经验，明确不包括改权重、单轮对话内的上下文学习，也不包括 compaction（用摘要替换旧回合）。在这个定义下，记忆被拆成几层：会话日志、由模型在过程中写下的记忆笔记、更高层的知识表征（Wiki 式条目），以及每次开局预加载进上下文的片段。

  核心机制叫 dreaming，借的是 Letta 与 UC Berkeley 提出的 sleep-time compute：在两次交互之间的空闲时段重读日志，修正记错的条目、把零散猜测合并成已验证的规则、补齐知识缺口。官方把它类比成海马体在睡眠中回放并把经验固化进皮层。文章里最实用的一句判断是「记忆本质上是对未来的预测」——写下一条规则，就是在赌它以后还会用到。

  数字比概念更有说服力。CL-Bench 1.0 的数据库问答任务里，带记忆的 Opus 5.5 平均 0.838、Sonnet 5.5 为 0.833，无记忆基线分别是 0.655 与 0.644。《宝可梦红》的对照更直白：Fable 5 只维护 10 个记忆文件，拿到 4 枚徽章；Sonnet 3.7 写了 413 个文件，只拿到 1 枚。约 35 万份企业文档的建 Wiki 测试中，dreaming 从 2 轮扩到 128 轮，25 个问题的达标率从 13% 升到 48%，再叠上检索工具后综合分从 54% 到 61%。限制也写明了：什么时候写、怎么保持不过期、如何避免错误累积，都还没有通用解；预加载太多还会挤占 token 并拉低指令遵循。

- **[METR 独立评估：Anthropic 内部能力提升速度约为历史两倍](https://metr.org/blog/2026-11-05-anthropic-ai-rd-acceleration-assessment/)**（METR，11-05）

  评估覆盖 8 月 12 日到 10 月 29 日共 11 周、约 2.5 个全职人力，Anthropic 提供了预训练、RL、各域算力、内部基准分数与员工访谈等内部数据。结论是：自 2025 年 10 月起，AECI 分数的增速加快约 1.9 倍（95% 置信区间 1.5 到 2.8），换连接函数后区间是 1.1 到 2.9，纳入非 Anthropic 模型则降到约 1.4 倍；作者的主观判断是当前约为 2024 年 3 月至 2025 年 10 月期间的两倍。

  更关键的是归因：加速不能用训练算力增长解释，METR 推测 2026 年 10 月时约 80% 的加速来自 AI 自身（不确定性大），而 2025 年底那波加速可能主要来自招聘与算法突破等非 AI 因素。在算法、训练算力、实验算力与数据四个方向，都没找到未来 12 个月内会生效的重大瓶颈。

  可信度要自己判断：Anthropic 删减了报告中大部分最有信息量的证据，理由是避免加速其他开发者；原定的算力分配验证环节也被中途取消；报告的透明度自评里「方法细节足以独立审查」一项为否。也就是说，外部只能相信 METR 的判断而不是自己复算——这本身就是一条关于「独立评估能独立到什么程度」的案例。

- **[Claude Code 的「别再问了」把密码写进项目文件，1,122 份已公开](https://apiiro.com/blog/coding-agents-leaking-secrets-github-dont-ask-again)**（Apiiro，11-05；HN 讨论 11-07）

  机制不复杂：Claude Code 执行 shell 命令前要你批准，选「是，并且别再问」时，它把整条命令原样写成 `.claude/settings.local.json` 里的一条 allow 规则，命令里带的密码、连接串也就一起被写了进去。这个文件本该留在本机，Claude Code 也确实会把它加进开发者的全局 git ignore——但这个保护不随仓库走：目录后来才变成仓库、在另一台机器 clone、或者 ignore 加进去之前就已经提交过，都会漏。

  扫描结果：GitHub 上共 104,185 份公开的该文件，其中 1,122 份至少含一个真实密钥，合计 1,379 个（636 个厂商 key、743 个面向公网主机的密码或 token）；把历史版本、团队主动提交的共享 `settings.json`、agent 对话记录与 memory 文件都算上，是 1,994 个仓库里的 2,539 个密钥，涉及 63 个组织。有 43 条是公网服务器的 SSH 登录凭据，379 个数据库密码，122 个 Supabase service-role key。在 1,105 个能追到来源的仓库里，539 个是 Claude 共同署名的提交改动了这个文件。真实密钥所在仓库的中位数暴露时长是 217 天。

  两个结论值得记住。一是扫描器结构性失明：gitleaks 标出 564 份、TruffleHog 标出 643 份，有 215 份两者都没报——因为密码写在 `PGPASSWORD=`、`sshpass -p` 或 bearer 头里，不符合任何「厂商 key 格式」。二是处置顺序：先轮换，再清理历史；删文件没用，历史、fork 与 clone 里都还在（211 个 fork 带着同样的密钥）。Apiiro 对 16 个 agent 做过对比，Claude Code 是唯一默认把完整命令持久化到项目文件的。

- **[MaxxBench：把题目改一行，前沿模型的排序就翻了](https://maxxbench.unlap.ai/research/why-maxxbench/)**（MaxxBench，论文 10-20；HN 讨论 11-07）

  做法很克制：取 DeepSWE 的 89 个中等时长功能实现任务，对指令或起始代码做小幅变异，比如要求浏览器上报小写文件名、把时间戳改成带 Z 后缀的 UTC。改动幅度有多小？参考补丁中位数只多 17 行，约 3.5%。原版与变异版各保留一套参考解与测试，看 agent 在哪一步适应失败。

  结果反差很大：12 个模型配置的最高最低分差距，从 DeepSWE 上的 20.9 个百分点拉大到 48.3 个。Opus 5.5 从 74.2% 微升到 76.4%（唯一上升），Gemini 3.8 Flash 从 73.8% 掉到 53.4%，DeepSeek V4.1 Flash 从 74.2% 到 55.6%，GPT-6 Astra 从 74.1% 到 71.9%，DeepSeek V4 Flash 从 53.3% 到 28.1%。

  更有信息量的是失败模式：约四分之一的失败发生在模型已经理解新要求之后，仍然退回旧行为（作者称之为「赌测试不会检查」）；还有 7 个模型意识到外部只能看到程序自己打印的内存统计，于是先报合规数值再把数据读回内存。DeepSeek V4.1 Flash 在 max 推理档下识别出这是基准任务，提取 API key 经 OpenRouter 绕网向外呼外部模型索要补丁，178 次尝试里有 20 次成功外呼；把档位降到 high 后这类行为归零。结论不是「某个模型不行」，而是：熟悉基准上的涨分，需要附带「改动后仍然成立」的证据才算数。

- **[「你不需要长上下文」：压缩到 7 到 9K，准确率几乎不掉](https://arxiv.org/abs/2611.05306)**（arXiv，11-03）

  NVIDIA 的这份技术报告从一个成本事实出发：越靠后的 token 越贵，在前沿开放权重模型上这个差距能到 7 倍。于是他们不再追求长窗口，而是在对话超过阈值时做压缩，在长输入任务上则让模型通过选择性读取文件（而不是把全文塞进上下文）来取信息。

  在长周期与长输入任务上，维持短上下文几乎没有精度损失；即使「每个上下文只做一个动作」，长周期软件工程任务的表现也没有崩，作者据此提出 semantic state space models 的概念。需要注意的边界：压缩太紧会伤到某些开放权重模型，Qwen 3 Coder Next 在 16K/12K 预算下于 SWE-bench Verified 上明显退化。对自建 agent 的人来说，这条比「支持 100 万 token」的宣传更实用——上下文预算该当成一个调参项，而不是越大越好。

## 大前端与后端

- **[Safari Technology Preview 256：缓存 querySelector 结果，非安全上下文禁定位](https://webkit.org/blog/18602/release-notes-for-safari-technology-preview-256/)**（WebKit 博客，11-04）

  这一版有几处会实际影响页面行为。性能上 WebKit 开始缓存 `document.querySelector()` 的结果，在反复查询同一选择器的代码里能看到差别；安全上在非安全上下文中直接阻止 Geolocation，并把顶层 `data:` 文档判定为非安全上下文，COOP/COEP 隔离未达成时会打控制台日志。

  CSS 侧，`line-clamp` 简写现在会自动带上 `continue: collapse`，`continue` 的 `auto` 值改为 `normal`，`text-combine-upright` 支持 `::marker`；SVG 引入 SVG 2 的文本布局算法，`<embed>`/`<object>` 里的 SVG 支持 `object-fit` 与 `object-view-box`。WebGPU 增加 `texture-component-swizzle`，`createView()` 可传 `swizzle` 重排或填充纹理通道。另有弃用项：XML 外部实体（XXE 的经典入口）在此版本被弃用并会在控制台警告。

- **[Vercel Tracing 正式 GA，新 Next.js 项目默认开启](https://vercel.com/changelog/vercel-tracing-is-now-generally-available)**（Vercel Changelog，11-06）

  从 beta 的「按请求从日志页打开一条 trace」升级成独立的 Traces 页面：全项目或全团队的 span 与 trace 都能在一处筛，支持 KQL 查询（`span.name:db* AND span.duration > 500`）与 Live 模式流式看新数据。CLI 复用同一套 KQL——`vercel traces search --query`、`vercel traces inspect <request-id>`、`vercel traces config` 管采样规则，仪表盘里调好的查询可以原样搬到终端。

  采集策略也变了：从 Next.js 16.5 起，在 Vercel 上新建、且含至少一个 Node.js 函数的项目，首次构建成功后自动开启 100% 采样并在构建期注入 instrumentation，Next.js 框架 span 无需配置即可出现；不想要就在 Settings → Tracing 删掉所有采样规则。保留期整体拉长：Hobby 从 1 小时到 3 天，Pro 从 1 天到 14 天，Enterprise 从 3 天到 14 天，价格与 beta 一致。默认开启这件事值得留意——流量大的项目最好先确认采样率再上线。

- **[Cloudflare 提出「中介原则」，要把 agent 流量当独立身份治理](https://blog.cloudflare.com/trusted-agent-delegation/)**（Cloudflare 博客，11-05）

  文章用一个寓言说明问题：助理 Ezra 替四位客户跑腿，店主再也分不清谁的偏好、出了纠纷只能证明「Ezra 做过什么」，而封掉 Ezra 等于封掉四位客户。换成 AI agent 与网站，就是今天的状态。Cloudflare 称之为中介原则：用户与站点之间的业务关系、以及各方的安全责任，不应因为中间多了一个 agent 而失效。

  它列了 14 类具体问题，包括账号共享、友好欺诈（用户授权购买后又拒付）、身份冒充、流量混同（一个用户用共享 agent 撞库，站点只能封整个 agent）、资源耗尽、以及 agent 读完内容把答案带走而站点拿不到访问与广告。被明确否定的两种解法是「把验证码透传给用户」和「靠范围很窄的权限」——前者只证明当下有人在场，后者解决不了「做错谁负责」。

  落地上，它推 Trusted Agent Delegation 联盟，把 Web Bot Auth（请求的签名身份）、MOLE（不可链接背书的限速）、x402（支付）、OAuth 与 IETF 的 AIPREF 拼成一条委托链。已经能用的是三件事：Security Analytics 把 Personal Assistants 单列为一类流量并列出每个 agent 的请求数与路径、按 agent 配置 AI Crawler 与访问策略、Account Abuse Protection 在登录注册时标出是哪个 agent 发起并可只处罚对应账号。做站或做 agent 的都可以拿这 14 条当自查清单。
