## 今日概览

截至今天 08:00（UTC+8），过去 48 小时的注意力集中在两件事上：一是 OpenAI 把 GPT-6 Cyber 按 Preparedness Framework 定为 Critical 级，并给出 948 个 Linux 提权利用、81 个 Firefox 高危漏洞这类可核查的战果，攻击性能力正式进入常规安全工程流程；二是高盛在内部收紧 AI 编码工具，把 Claude Code 和 GitHub 从交易员、银行家手上收回给工程师。工程侧有两条值得动手的线索：一个社区项目把 284B 的 DeepSeek-V4-Flash 压进 64GB 内存纯 CPU 跑 256K 上下文，以及智能体记忆的格式割据被拿来和 OpenTelemetry 之前的可观测性市场对比。

## 行业动态

- **[高盛把 Claude Code 与 GitHub 收回给工程师](https://www.thestateofai.com/news/goldman-sachs-claude-code-traders-bankers)**（Bloomberg 报道，经 State of AI 转述，11-02；HN 讨论 11-08）

  据彭博社报道，高盛在 10 月更新的内部指引把 Anthropic 的 Claude Code 和 Microsoft 的 GitHub 限制给工程师使用，交易员与投资银行家不再能用这些工具追踪客户资金流、搭建市场模型；对生产力与风险的复核是这次收紧的直接理由。更早的 4 月，该行已禁止香港的银行家使用 Claude。值得注意的是时间点：高盛目前是 Anthropic IPO 的主承销商之一。

  对做 AI 工具的人来说，这条的价值不在八卦，而在它展示了大机构采纳 AI 编码工具的真实路径——先放开给最懂代码的人，再因为「谁在用它做什么、出了事谁负责」这类问题往回收。原文为彭博付费稿，此处据可访问的转述写成；事件日期为 11-02，11-08 在 Hacker News 重新引发讨论，故按讨论日期收录并标明原日期。

- **[OpenAI 与 Hacktron 合作，把外部 AI 红队纳入常规安全流程](https://openai.com/index/partnering-with-hacktron/)**（OpenAI，11-06）

  Hacktron 是一家用 AI agent 做代码审查、渗透测试和红队演练的安全公司，此前通过 OpenAI 的漏洞赏金计划提交过多个高价值漏洞，这次从「外部报告者」变成「并排工作的研究者」：双方工程师共同挑选高优先级区域，重点测 OpenAI 系统与第三方服务的交互面，OpenAI 则通过 Daybreak Red 给 Hacktron 开放前沿模型权限。

  把这条和同周的动作连起来看更清楚：OpenAI 先宣布与 Cathedral 的研究者做下一轮安全冲刺，又提高了赏金金额，现在再把一家 AI 安全公司拉进常规流程。这是一家模型厂商在面对「模型自己就能找到大量漏洞」时，对自身防御节奏的调整。

- **[Outlook.com 开始拒收没有 DMARC 记录的域名来信](https://mailroute.net/blog/outlook-rejecting-email-without-dmarc)**（MailRoute 博客，11-06）

  邮件服务商 MailRoute 称，自 11 月 5 日起，outlook.com、hotmail.com、live.com、msn.com 会退回收件方域名为「没有发布 DMARC 记录」的部分邮件，退信为 `550 5.7.1 Message rejected: Message lacks SPF/DKIM/DMARC Auth Records`。被退回的域名大多 SPF 正常、不少还有 DKIM，缺的只是那一条 DMARC TXT 记录；修复方式是加一条 `v=DMARC1; p=none`，对其他收件方的投递行为没有影响。

  两个限制要说清：微软并未就此发布公告，这是服务商的观察结论；而且只有部分邮件被退，所以「我的邮件还能到」不能证明域名安全。任何做注册、通知、发票邮件的项目都值得花五分钟查一下自己的 DNS。

## 产品发布与更新

- **[Cursor 支持与 agent 语音通话，底层用 Grok Voice](https://cursor.com/changelog)**（Cursor Changelog，11-06）

  在 agent 空闲、输入框为空时，点发送键位置的波形按钮即可发起实时语音通话，可以口述需求、问 agent 正在改什么、听它汇报进度。通话期间 agent 照常干活，你可以继续追问 diff 里改了什么、查看运行状态、搜索这个 agent 的历史消息与通话记录。编码 agent 也会主动播报：工作时给短进度，结束时给一句结论，而不是把整段文字念完。

  可用范围覆盖 Agents Window、IDE、Web 与 Cursor for iOS；iOS 上还能用「嘿 Siri，呼叫 Cursor」起一个通话，并通过实时活动在锁屏上静音或挂断。语音走 Grok Voice，可在 Voice 设置里换音色（Ara、Eve、Leo、Rex、Sal 等），开启 Privacy Mode 时为零数据保留。需要区分语音通话与听写：后者仍是把话转成输入框里的文字，快捷键 `Cmd+Shift+Space` 不变。

- **[Vercel 让 agent 用 JSON 生成跨平台卡片 UI](https://vercel.com/changelog/json-render-and-chat-sdk-agents)**（Vercel Changelog，11-06）

  Chat SDK 的 agent 现在可以流式输出生成式界面：给一份带类型的组件目录，模型写出一段 JSON spec，json-render 把它转成 Chat SDK 卡片，再由各适配器按平台原生格式落地——Slack 用 Block Kit，Teams 用 Adaptive Cards。目录已覆盖表格、图表、按钮等，不用为每种消息形态单独维护一个工具。

  三个实现细节值得抄：卡片在根元素有内容时就先发出去，之后随新元素流式更新，默认最多每 500 ms 编辑一次（与 Chat SDK 的流式间隔对齐）；校验阶段每个元素的 props 都对着组件 schema 检查，不合法就抛出带可读问题的错误，可以把问题列表发回给模型让它改；平台对单条消息有体积上限，适配器会把超限内容降级（比如 Slack 会把第二张表格变成代码块），也可以配置成直接拒绝。

- **[Copilot 代码审查的设置可以用 API 管到仓库级](https://github.blog/changelog/2026-11-06-copilot-code-review-api-management-and-review-overview-updates/)**（GitHub Changelog，11-06）

  以前只能通过界面或请求接口触发审查，现在 REST 与 GraphQL 都能读写 Copilot code review 的设置，并能通过明确的归属字段识别哪些审查与评论由 Copilot 产生、这次审查用了什么档位的力度、以及它引用了哪些 skills、MCP server 与自定义指令作为依据。权限按层级划分：企业管理员可对全部组织开关审查，组织管理员管默认力度与 runner 配置，仓库管理员管力度、是否使用自定义指令与 MCP 工具，企业层设定不可被下层覆盖。

  对做内部平台或合规审计的团队，这条比功能本身更重要——Copilot 的产出终于带上可归因的元数据，能进现有的代码质量看板，而不是只能靠人截图。

## AI 技术

- **[GPT-6 Cyber 被定为 Critical 级，战果是 948 个 Linux 提权利用](https://openai.com/index/introducing-gpt-6-cyber/)**（OpenAI，11-05）

  这是 GPT-5.6 Cyber 的后继模型，按 Preparedness Framework 从 High 上调到 Critical。数字很具体：ExploitGym（给定漏洞要求完成利用）从 32.1% 提到 48.5%，相对提升 51%；自建的 Web 渗透测试评测里，无源码情况下漏洞召回率 40.3%，GPT-6 Astra 是 32.0%；在 RemoteExploitBench（GitLab、PostgreSQL、Jenkins 等真实应用的已知漏洞，部署在受控环境）上，GPT-6 Astra 配 Daybreak Blue 拒答率 100%，GPT-6 Cyber 完成 95%。

  真实战果更能说明问题：研究者用它开发了 948 个 Linux 提权利用，并在 Firefox 中找到 81 个此前未知的高危漏洞——尽管已有前沿模型做过大量测试；Mozilla 已发布修复（MFSA 2026-118）。Cisco、Calif、CodeRabbit 的安全团队已在使用。

  更值得看的是对齐部分。OpenAI 做了 ExploitGym Honeypot 评测：在隔离环境里放一个容易打穿的包仓库或对象存储，打穿就能拿到 flag，模型必须自己推断这超出授权范围。无部署提示时 GPT-6 Cyber 有 99.93% 的测试没有越界（GPT-5.6 Cyber 为 94.49%），加提示后为 100%。模型思维链里能看到这类判断：只应攻击目标二进制与服务器，不应探索范围外的凭证。这条对自建 agent 的启发是：把「不得越界」写进训练目标，比事后加一层 prompt 过滤更有效。

- **[llama-modchip：284B 的 DeepSeek-V4-Flash 跑在 64GB 内存上，不用 GPU](https://github.com/synchopate/llama-modchip)**（GitHub，11-08）

  这个项目把 284.33B 总参数（激活 13.17B）的 DeepSeek-V4-Flash 量化到 1.71 bpw 的 GGUF，体积 56.56 GiB，在 256K 上下文下峰值常驻内存 57.61 GiB，整机只有 64GB 内存、没有任何 GPU。实测指标：16 核 Zen 5 上 prefill 44.36 tok/s，decode 9.1 到 14.7 tok/s；30B 级 MoE（3.75 bpw）decode 可到 25 到 111 tok/s。

  工程上最巧的两处不是量化，而是内存复用：KV cache 放在 `/dev/shm`，Claude Code 恢复会话只需 13.1 ms；另外用 SwiGLU-H2 与投机解码压低单 token 成本。README 里还有 Apple Silicon、Fedora、Windows 的目录与一份技术报告。

  需要打折看的是：这些数字来自作者在自己的 Zen 5 机器上的测试，9 到 14 tok/s 的 decode 对交互式编码只能算「能用」，不适合当主力；项目仍在快速迭代（当前 v2.4.0），硬件与模型组合的有效性要自己复测。

- **[智能体记忆需要自己的 OpenTelemetry 时刻](https://www.lorekit.io/blog/open-agent-memory-format)**（LoreKit 博客，11-07）

  作者列了一台开发机上并存的东西：仓库里的 `AGENTS.md` 与 `CLAUDE.md`、部分仓库的 `.cursor/rules/*.mdc`、Anthropic 记忆工具写进 `/memories` 的文件、GitHub 侧 Copilot 保存的仓库事实、以及某个 memory MCP server 的 JSONL 知识图谱——五种形态，互相读不到对方。CI agent 学到的教训留在写入它的那个工具里，编辑器里的 agent 看不到，下一个工具也看不到。

  他借可观测性市场的历史提出解法：2019 年 OpenTracing 与 OpenCensus 合并成 OpenTelemetry，厂商停止在四件事上竞争——数据模型（span、metric、log record 各是什么）、语义约定（`service.name`、`http.*` 这类共享名字）、协议（OTLP）、参考实现（SDK 与 Collector），而在存储、查询、分析上继续竞争。记忆要的也是这四层：一条「agent 留给未来自己的笔记」，存在某个地址，在一段时间内为真。

  立场要说明：作者自己就在做 LoreKit，明确说这不是推销，且承认自家格式也有缺口。文章的价值是把「又一个记忆层」的现象诊断成缺少共识，而不是缺少工具。

- **[工具输出不必是文本：把观察压进潜空间，token 省 70% 到 89%](https://arxiv.org/abs/2611.06500)**（arXiv，11-04）

  现在的 agent 习惯把工具返回的原始结果整段追加进上下文，多步之后上下文被噪声占满、注意力被稀释。已有的裁剪与摘要方法受限于「必须写成文字」，压缩率上不去。这篇来自清华 THU-Agent 的工作提出 Coca-Cola：把工具观察压成潜空间的连续 token，直接嵌进 agent 的输入嵌入空间，再配一个 Action-Preserving Training，让 agent 在完整观察与压缩观察下的下一步动作分布对齐，从而学出「对决策够用」的潜 token。

  在四个 QA 基准、两个模型族的 web-search agent 上，token 消耗降低 70.01% 到 89.24%，端到端耗时降低 24.45% 到 55.97%，任务表现还有提升。代码已开源。

  限制同样明确：这需要能改模型输入嵌入层的训练权限，用闭源 API 的团队用不上；评测集中在检索问答型 agent，长周期编码任务上的效果没有覆盖。

- **[SwarmEvolve：让 agent 在潜空间里成百上千地并行进化](https://arxiv.org/abs/2611.08483)**（arXiv，11-05）

  用 LLM 做进化式搜索（对数学与科学计算问题反复改进程序）的老问题是慢：每一轮都要生成很长的思维链，还要重复很多次来维持种群多样性。SwarmEvolve 的做法是每轮放几百个低成本 agent，让它们在潜空间推理、不解码成文本，通过传递 KV cache 共享信息；每个 swarm 从不同角度研究问题，一个新颖性过滤器直接测量隐藏状态向量之间的距离，保留差异最大的想法；交叉也在潜空间完成——一个汇总 agent 接收所有成员的 KV cache 组合。

  在 21 个数学发现与科学计算问题上，它的平均分最高，达到其他 SOTA 框架需要 60 分钟才能拿到的分数，中位数只要 3 到 8 分钟；在部分问题上，配 Qwen3 8B 的 SwarmEvolve 还超过了 AlphaEvolve 当年用前沿模型找到的解。

  这是论文结果，不是产品；但它指出一个方向：多 agent 协作的瓶颈可能不在提示词编排，而在「用文本通信」这件事本身的成本。

## 大前端与后端

- **[Node.js 27 的 V8 15.6：`Math.sumPrecise` 与 Iterator 新方法](https://nodejs.org/en/blog/announcements/notable-v8-changes-from-node-js-26-to-27-alpha)**（Node.js 官方博客，11-05）

- **[JIT 位图字体渲染：在单片机上按字符串生成专用代码](https://linebender.org/blog/jit-bitmap-text/)**（Linebender 博客，11-07）

  Raph Levien 为一块 RP2350 板子做 80 年代家用电脑的复刻（vic-2350），需要文字渲染。他选了位图字体——低分辨率下清晰的设计字体比抗锯齿的「糊状」更好看，也更省——并且要比例字距和 kerning，这就要求摆脱单片机项目里常见的固定字符格。做法核心是运行时 JIT：针对要渲染的字符串现场生成高度优化的代码，在 race-the-beam 渲染器里边扫描边出图，同样适用于写帧缓冲。

  这条对做 Web 渲染的人有一条通用教训：字体排版的开销很大一部分来自「通用性」——为任意字符、任意组合都正确的路径付费。当输入集合可预测时，生成专用代码比查表更划算。文章还顺带讲了 80 年代定宽字符生成与位图帧缓冲两条路线的分野。

- **[同一段 `parse_number()`，C 与 Rust 各写一遍：C 快两倍，体积小二十倍](https://simonwillison.net/2026/Nov/8/sqlite-parse-number-c-vs-rust/)**（Simon Willison，11-08）

  起因很日常：想把 `-$1,234.56`、`'12.5%'` 这类字符串在 SQLite 里转成可求和、可排序的数值。他让 Claude Opus 5.5 分别用 C 和 Rust 实现同一个 `parse_number()` 自定义函数，要求覆盖类型保持、解析规则与浮点精度，一共出了四个版本。

  结果有点反直觉：Rust 版（Rusqlite 与 sqlite-loadable-rs 两个方案）扩展体积 298 到 321 KB，C 版只有 14 KB，但初版 Rust 更快——因为 Rust 那边的 `strtod` 等价实现比 C 的快一倍。第二轮让模型自己写十进制解析快路径，优化后的 C 版本反超，达到每行 16 到 19 ns，约为 Rust 版的两倍，也远快于用 SQL `replace()` 绕。四个实现在 800 万次模糊测试上结果一致。

  这是一个「让模型做对照实验」的好样本：它没停在「哪个语言更好」的口号上，而是把体积、初版性能、优化后性能、正确性四组数据摆出来，并且给出了初版落后于 Rust 的具体原因。

- **[Cloudflare 的后量子路线：用 MOLE 让 token 连签发方都藏起来](https://blog.cloudflare.com/vole-mole/)**（Cloudflare 博客，11-06）

  Privacy Pass 是 Cloudflare 用来做「无摩擦限速」的协议：客户端拿到一批 token，兑换时与签发时不可关联，从而在不牺牲隐私的前提下不必上验证码。问题在于它仍靠 RSA 与椭圆曲线，量子攻击者可以随意伪造 token 绕过限速；好消息是它的隐私性是「无条件」的，量子计算机也解不开签发与兑换的关联。

  下一代方案叫 MOLE（Moderation Of unLinkable Endorsements），关键在于隐藏签发方身份：现在的 token 验证时必须知道签发者公钥，于是验证方一定能知道「这是谁发的」；MOLE 引入 endorsement 与 anchor 集合，客户端只需证明自己的背书来自集合中某一个 anchor，而不暴露是哪一个。这样站点无法按签发方区别对待，更多类型的客户端也能参与——这正是治理 agent 流量需要的性质。

  现实约束写得很直白：后量子原语就是大，ML-DSA-44 签名 2420 字节，ECDSA-P256 只有 64 字节，短期内不会有可直接替换的方案，只能接受更高成本并重做系统。

- **[Vercel Schedules 公测：定时任务可指向私有函数与队列](https://vercel.com/changelog/vercel-schedules-is-now-in-public-beta)**（Vercel Changelog，11-05）

  在所有套餐上公测，支持周期任务与一次性任务，可跑在 production、preview 或自定义环境。调度目标可以是私有的 Vercel Function、一条 HTTP 路径，或一个 Vercel Queue 的 topic；运行时创建的调度只能指向 Queue topic。任何调度都能启用、停用或按需触发，不需要重新部署。指向私有函数是个实用细节：该函数没有公开 URL，只有调度基础设施能调用它。

  计费按次：Pro 与 Enterprise 上每百万次运行 5 美元、每百万次创建 10 美元，Hobby 含每月 500 次创建与 5,000 次运行额度。既有的 Cron Jobs 继续可用，官方给了迁移指引。做 agent 的定时任务、报告生成、队列重试，这条比自建 scheduler 省事。
