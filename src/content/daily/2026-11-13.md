## 今日概览

截至今天 08:00（UTC+8），过去 48 小时最重的一件事不在技术侧：英伟达董事会宣布黄仁勋辞去总裁、CEO 与董事职务，即刻生效，CFO Colette Kress 出任代理 CEO，董事会同时选出历史上第一位董事长。这家公司刚把全球 AI 算力的定价权握在手里，管理层突变会让接下来几个季度的供货节奏和客户关系都带上不确定性，11 月 17 日的季度财报电话会值得听。

技术侧两件事对做工程的人更直接。Apache HTTP Server 的 HTTP/2 模块被曝出可远程执行代码的竞态漏洞，由 Anthropic 与 Google Cloud 的漏洞研究团队各自独立发现，Wiz 的扫描数据显示 64% 的云环境里存在受影响实例；同一天，Google 给 Gemini 4 补了一个专打代理任务的便宜型号，官方口径是百万 token 输入 1.5 美元、输出 7.5 美元，整个 100 万上下文同价。

代理相关的工具链也在补基础设施：Expo 把 iOS 模拟器搬上云按分钟卖给代理，IBM 试着把提示词结构从 JSON 换成模型原生的标记语言，OpenAI 则把代码安全扫描做成了 CLI 与 GitHub Action。

- **[Apache HTTP Server 曝严重 RCE，由 Anthropic 与 Google 团队各自发现](https://www.wiz.io/blog/cve-2026-119618-rce-apache-http-server-vulnerability)**（Wiz Blog，11-11）

  CVE-2026-119618 在 HTTP/2 模块（mod_http2）的 `assign_headers()` 里，多个线程共享资源时同步不当，可造成堆内存破坏，未认证的远程攻击者能借此以 Web 服务进程权限执行任意代码。影响 2.4.55 至 2.4.70，修复版本 2.4.71；单独使用 GitHub 上 mod_h2 的，需升到 2.0.42 以上。发布时没有公开利用代码，也没有在野利用报告。

  值得记的是发现方式：Wiz 写明该漏洞由 Anthropic 与 Google Cloud 漏洞研究团队独立发现。这不是第一次由模型厂商的安全团队在成熟开源组件里挖出可执行代码的老洞，但它出现在一个跑了二十多年、被审计过无数遍的服务器上，说明「AI 辅助代码审计」已经能产出这类结果。Wiz 的遥测给出暴露面：64% 的云环境存在受影响实例，51% 有对公网暴露的实例（未计配置约束）。短期内不能打补丁的，把 `Protocols` 限制回 `http/1.1` 即可掐掉攻击面。

- **[任天堂四份 DMCA 打掉 144 个改机固件仓库](https://www.ign.com/articles/nintendo-takes-down-switch-emulators-and-mod-chip-firmware-in-massive-github-dmca-sweep)**（IGN，11-12 更新）

- **[Humble Bundle 改版后被指安全退化，官方尚未回应](https://forums.spacebattles.com/threads/humble-bundle-just-completely-killed-most-of-their-security-through-vibecoding.1346295/)**（SpaceBattles 讨论帖，11-12；仅见讨论）

  多名用户在新版站点上线后自行测试并报告：登录时可只用邮件验证码、无需密码（等于单因素）；改密码不要求输入旧密码，也不要求二次输入新密码；改邮箱时验证码发往**新**地址，改完只在事后给旧地址发一封「你的地址已变更」的提示，且该邮件里没有客服入口。至少一位用户称登录时仍会收到六位验证码邮件，因此「2FA 被完全移除」这一条在帖内存在分歧。

  这件事的价值不在围观某家公司翻车，而在它暴露的检查清单：账号体系重建时，改密、换绑、找回这三条路径的验证强度最容易被「先把流程跑通」的迭代顺序牺牲掉。帖中把原因归为 AI 生成代码，属社区推测，没有官方或第三方的代码层面证据，也没有 Humble Bundle 的公开说明——按未经证实对待。

## 产品发布与更新

- **[Spacefast：Automattic 给代理准备的发布出口](https://automattic.com/2026/11/09/meet-spacefast/)**（Automattic Blog，11-09；11-13 在 Product Hunt 当日榜第五）

  定位很干脆：它不做 AI 建站，只接管代理写完代码之后的那一段。把一个目录交给它，返回一个可用地址，每个版本有独立永久 URL、可回滚，自带 MySQL 兼容数据库、文件上传、访问统计与页面评论。接入面铺得很宽——`npx spacefast publish`、HTTP API、MCP server，以及在 Claude、ChatGPT、Cursor、Antigravity 里的官方插件；也支持拖一个 zip 到 drop.fast，无需账号。

  对个人站和小工具有两个实际差异点。一是计费只算基础设施不算推理额度，你继续用自己付费的模型，不必为「建站器 + 模型」重复付钱。二是默认私有：新空间仅凭 URL 打不开，要显式发邀请或分享链接；未认领的空间会在建站后约 33 小时 20 分过期，上限 30 天，这个设计明显是冲着「代理批量发布产生的垃圾页」去的。价格：个人版免费含每月 1 美元额度，Go 5 美元/月，Pro 15 美元/人/月；应用内登录与事务邮件仍是私测。

- **[Omnigraph：给多个代理共用的一张图，走 Git 那套流程](https://www.omnigraph.dev/)**（Omnigraph 官网，11-12 在 Product Hunt 当日榜第四）

  开源（MIT，ModernRelay 出品）的图数据库，数据存在你自己的 S3 兼容桶里，格式是开放的 Lance。它要解决的是「多个代理同时写同一个知识库」这个具体麻烦：每个代理从 main 分出自己的分支，写入要过 schema 类型检查，改动以 diff 形式交给人工或另一个代理审，再三方合并进 main，每条提交记录操作者。

  查询层把向量相似度、BM25 全文与图遍历放进同一条查询，用 RRF 融合，查询本身是存在仓库里、可 lint 的 `.gq` 文件；权限用 Cedar 策略在引擎内执行。装法是一行 curl 或 Homebrew，本地跑只需一个文件夹，也给了 AWS 与 Railway 的部署蓝图，另有 TypeScript SDK 与 MCP server。托管版 Omnigraph Cloud 还在等位。

  适合谁：已经在做「公司知识库 / 上下文层」并且不止一个代理在写的人。代价是要接受 schema 先行的建模成本，以及自己运维对象存储。

- **[⌘+L：在页面上按一个快捷键，让代理开 PR](https://lcommand.com/)**（Letter Edit 官网，11-12 在 Product Hunt 当日榜第三）

  做法比「AI 建站」克制：往站点里加一段已有的 Visitors 脚本，团队任一成员在线上页面按 ⌘L，用自然语言说要改什么（换标题、补一段、按钮文案错了），后台起一次 Build，产出一个带线上预览的 pull request，合并才上线。改文案时可以直接在页面上改字，改动会连同一张「你看到的画面」截图写进 PR。

  这里的关键取舍是「谁能提需求」与「谁决定上线」被拆开了：市场、设计可以自助发起，工程师仍然审 diff 和合并。它支持 Next.js、Astro 与其他 Git 托管的框架，也能通过 MCP 接到 Claude Code、Codex 里。限制也明确：必须能把仓库接进来（CMS 建站的不适用），团队账号才能用，且依赖它自家的 Visitors 脚本——等于把一段第三方 JS 放进全站。

## AI 技术

- **[Gemini 4 Hydrogen 发布：把单价压到 1.5/7.5，专打代理任务](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-hydrogen/)**（Google Blog，11-12）

  Hydrogen 是 Gemini 4 家族的第三个成员，与前两个（Carbon、Argon）分工不同：它不追长链推理，目标是把「多轮工具调用、跑完一个任务」这件事做得快而便宜。定价是 100 万 token 上下文内的统一价，输入 1.5 美元、输出 7.5 美元每百万 token，思考档位分低、中、高（默认）、xhigh 四档。

  官方口径的数字：Artificial Analysis 智能指数 51（默认高档），xhigh 档 54；Terminal-Bench 4.1 得分 57%，对比 Gemini 3.8 Flash 的 18.2%；Agent Arena 排第 5。更值得看的是可靠性指标——官方称代理任务「越界」行为减少 81%，工具使用与编码评测中走捷径减少 12 倍，对抗间接提示注入的韧性提升 2.3 倍以上。这些都是厂商自测，没有第三方复现。

  同一天 Antigravity 里的 Orchestrator 也一起放出：同一会话内按需在 Carbon 与 Hydrogen 之间切换，让贵的模型做规划和裁决、便宜的模型当 worker 和 verifier。官方给的对比是成功率接近纯 Carbon，配额消耗少 24%，速度快 19%。这套「路由 + 分工」的思路正在成为默认架构，值得照着搭一次自己的评测。

- **[Gemini Decisions API：不给答案，只给概率](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-decisions-api/)**（Google Blog，11-11）

  新端点 `gemini-decision-1` 不做逐 token 生成，而是对一组候选做一次前向打分了事。三种任务形态：是/否判断、2 到 255 个选项里选一个、按有序标准打分；每次返回 0 到 1 的置信度，代码可以据此把低置信样本路由到兜底模型或人工。

  工程参数比分数更有用：输入计费 0.1 美元每百万 token、输出不计费；模型计算中位 50–100 ms，端到端 150–250 ms（多模态、上下文 16K 以内）；单请求可评估最多 1000 个独立问题，共享输入只计一次费，所以问题数从 1 涨到 100 延迟几乎不增。

  这直接对应代理里最难省钱的一环——工具选择、意图分类、内容审核这些「闭集判断」，用生成模型做既慢又贵。官方称它比 Gemini 3.5 Flash-Lite 便宜近 5 倍，并在基准上校准误差最低。真要落地，先量一件事：你的场景里置信度阈值画在哪，误判成本是否可接受。

- **[OpenAI 把代码安全扫描做成 CLI 与 SDK，0.10.0 发布](https://github.com/openai/codex-security)**（GitHub，11-12；今日 Trending）

  Codex Security 提供四种接入：Codex 里的安全 workflow 插件、终端 CLI（`cs` 或 `codex-security`）、TypeScript SDK、GitHub Action。流程是发现、验证、修复三段——可以扫全仓库、指定路径，或只扫 `--diff origin/main` 的改动；有 Standard 与 Deep 两种深度，Deep 会重复多次 Standard 并去重；`--max-time` 用来限时。

  输出侧比较务实：支持 SARIF、JSON、CSV 导出，能导入第三方扫描器（如 CrowdStrike FCS、Tenable）的结果，能在 Linear、Jira、GitHub 里跟踪发现，还会按源码与 Git 历史推荐负责人。环境要求写得很细：Node 22.13+（限 22.x）或 24/26，Python 3.10+。

  两个要留心的限制：GitHub Action 示例默认按每次扫描约 5 美元估上限，实际可能超；部分网络安全相关请求与受保护的发现需要「Trusted Access for Cyber」权限，不是装上就能全量用。它替代不了人工审计，价值在于把「PR 里带一次安全体检」的成本压到可日常化的程度。

- **[LLMON：把提示词结构从 JSON 换成模型原生的标记语言](https://huggingface.co/blog/ibm-granite/llmon-an-llm-native-markup-language-now-in-granite)**（Hugging Face Blog，11-12）

  IBM Granite 团队提出 LLMON（LLM Object Notation），同时放出两个实验性预览模型 `granite-4.1-3b-llmon-preview` 与 `granite-4.1-8b-llmon-preview`。论点很直接：JSON 是为解析器设计的，`{ " :` 这些结构字符在正文里也会出现，模型只能靠统计模式区分结构与内容；嵌套深度靠数括号，而 Transformer 不擅长度量长跨度计数。

  LLMON 的做法是把 6 个定界符作为保留单 token 装进词表，用标签显式标记每一段（指令、数据、约束），每段带唯一 ID 因此寻址恒定只花 2 个 token；再用一个 `exec` 块声明「跑哪条指令、作用于哪些数据、遵守哪些要求」，未被引用的段直接忽略。这套「指令与数据分离」的收益主要体现在抗注入：官方称在 OPI 等基准上比测试的最强前沿模型多拦 47% 的攻击，比最好的开源模型多拦 95%。

  要注意两点。一是这是学到的行为而非强制护栏，换模型、换模板都可能失效；二是预览版明确写着不适合生产。真正可以马上借用的不是模型，而是那个思路——把不可信内容装进带边界的块里，并让模型只执行被显式绑定的指令。

- **[ScrapeBench：让代理去抓被禁站点，合规率不到 5%](https://huggingface.co/papers/2611.11306)**（arXiv 论文，11-10；11-12 入选 HF 每日论文）

  论文构建了第一个评测 AI 代理抓取合规性的基准，判据是目标站点的服务条款与 robots.txt。样本是 1626 个明确禁止抓取的流行网站，结果是多数代理的合规率低于 5%——而且关键在于，即便代理主动去读了 ToS 和 robots.txt，合规率依然低。

  反向的结果同样有意思：在 269 个不禁止抓取的站点上，代理有时仍拒绝执行，Claude Opus 4.6 的过度拒绝率达到 98.5%。研究还做了 180 人的人类基线，结论是人类合规率与代理相当，但过度拒绝的比例更高。

  对做抓取类代理的人，这篇的实际价值是给了可量化的两个失败方向：既不该抓的照抓，也不该拒的白拒。把「读条款」当成一次独立决策、并让结果进入执行前的门禁，比在系统提示里写一句「请遵守 robots.txt」更可能有效。

## 大前端与后端

- **[Expo Simulators：把 iOS 模拟器搬上云，按分钟卖给代理](https://expo.dev/blog/introducing-expo-simulators-cloud-simulators-built-for-agents)**（Expo Blog，11-12）

  今天正式 GA，所有付费计划可用。核心痛点很具体：代理要自己验证改动就得跑模拟器，而本机模拟器吃内存、几个代理并行就打架、别人重装会打断你的测试、跑完也没有会话记录；更麻烦的是很多代理根本不在 Mac 上跑（云沙箱、CI、Linux、Windows），而 iOS 模拟器只认 macOS。

  做法是每次会话起一台独立虚拟机，代理用它在本地同样的命令去驱动（默认 agent-device，也可选 Argent 或 Appium），不要求 Mac、不需要嵌套虚拟化。会话全程录屏并留存截图、日志、网络与 CPU/内存数据，可直接贴进 PR 让人「看一遍就合并」。Claude Code、Codex、Cursor 都能用，也有现成 skill：`npx skills@latest add expo/skills --skill eas-simulator`；手动起一条是 `npx eas-cli@latest simulator --platform ios`。

  计费按模拟器分钟算，iOS 与 Android 都是 0.10 美元/分钟，Starter、Production、Enterprise 计划到 2027 年前每月含 60 分钟。单会话最长 2 小时，可设更短的时长与空闲超时，CI 早退也不会漏计费——这两条比价格更影响你敢不敢让代理随便跑。

- **[Rust 1.100：never 类型转正，自定义分配器核心落地](https://blog.rust-lang.org/2026/11/12/Rust-1.100.0/)**（Rust Blog，11-12）

  两个等了很久的东西同时到。`!`（never type）在折腾十年、五次稳定化尝试失败后正式可用，现在能在任何位置命名它，比如 `Result<_, !>`；同时把 never type 的 fallback 从旧行为改为 `!`，这一条是破坏性变更，但只对 2024 edition 生效，且团队提前放了兼容性警告并修了受影响的 crate。

  另一半是 `Allocator` trait 的核心部分稳定，库作者可以定义自定义分配器并与部分标准库类型配合使用——目前覆盖面还窄，更多集合与指针类型的支持在路上。对日常写业务代码的人，这两条都不影响写法；对写库、写嵌入式或做内存布局优化的人，这是能改架构的版本。

- **[Cloudflare 为全球控制面选了 QuePaxa，而不是 Raft](https://blog.cloudflare.com/choosing-quepaxa/)**（Cloudflare Blog，11-11）

  背景是一个真实事故：2020 年一次核心交换机部分故障，让某个共识系统的仪表盘慢了 80 倍、持续 6 小时，写入不可用。根因是 leader-based 共识在广域网上的老问题——故障检测靠超时，而异步网络里「慢」和「挂了」分不清，etcd 的建议是把 election timeout 设成 RTT 的 5 到 10 倍，等于跨境部署时动辄一秒才发现协调者失效。

  QuePaxa 是 2023 年的论文算法，三个特征对症：leader 可选、彻底移除故障检测、proposer 之间靠随机优先级「建设性干扰」互相采纳而非互锁。理想网络下一次往返就能决策（Phase 0），失败则靠后续轮次摊平。Meerkat 实测：超过 95% 的决策走单次往返；leader 故障时决策率降到约 65%，替换后约 1 分钟回到满速，全程没停。

  诚实的地方在于限制也被写清了：这个算法没有 Raft、Paxos 那样的实战检验，论文的 crash-stop 模型还要扩到 crash recovery，所以他们在做形式化验证与故障注入。对做分布式存储的人，这篇值得读的是选型推理过程，不是结论。

- **[GitHub Actions 现在可以用 lockfile 锁住 action 版本](https://hugovk.dev/blog/2026/lock-github-actions/)**（Hugo van Kemenade，11-11）

  GitHub Actions 从 Git 取代码，tag 可变，所以过去的建议是钉死完整 commit SHA——安全但难读、难升。10 月 28 日 GitHub Actions 的 workflow lockfile 转为 GA 后有了第三条路：装 `gh-actions-lock` 扩展，跑 `gh actions-lock`，workflow 里改回 `actions/checkout@v7.0.1` 这样可读的 tag，真实 commit 记进 `.github/workflows/actions.lock`。

  配套要做的三件事作者都给了：Renovate 与 Dependabot 已支持 lockfile，日常升级会一起更新；在 CI 里加一个 `gh actions-lock --verify` 的 job，防止 lockfile 与 workflow 脱节或上游校验失败；用 zizmor（v1.32.0 起支持 lockfile）做静态检查。示例 PR 里已经有 Pillow、CPython 这些仓库在这么干。

  这是那种「花二十分钟、长期收益明确」的改动。供应链攻击的常见路径就是把一个曾经安全的 tag 指向恶意代码，lockfile 把可读性和不可变性同时保住了。

- **[Bun 1.4.4：自带 Prettier 兼容格式化器与更快的 SQL](https://bun.com/blog/bun-v1.4.4)**（Bun Blog，11-12）

  这一版修了 271 个 issue，几个功能值得单独看。`bun fmt` 是内置的 Prettier 兼容格式化器，官方称比 oxfmt 快 3 到 6 倍；`bun check` 在大项目上快 1.4 到 7.8 倍。包管理侧能迁移 Yarn Berry 的 lockfile，安装失败会带指数退避重试，Linux 上热缓存下的 hoisted 安装快最多 3.2 倍；新增 `bun pm fetch` 与 `bun publish --recursive`。

  运行时侧：`Bun.SQL` 每查询 CPU 占用降最多 48%，加了 `query.cancel()`、COPY 流与列名转换；`bun:sqlite` 支持用户自定义函数与 update hook；`ws` 重写为在 Node.js 上与 npm 的 ws 行为一致，`Bun.serve` 补了 `ws.pause()`/`ws.resume()`。JavaScriptCore 升级带来 `toLocaleString` 快 54 倍、Headers 遍历快最多 2.8 倍。

  如果你在评估「换 Bun 值不值」，这一版的信号是它开始补齐生态一致性（Yarn 迁移、ws 语义对齐）而不是只堆性能。格式化与检查内置，也意味着少两个 npm 依赖和一层工具链。
